# GloBox Mobile App A/B Testing Experiment

An end-to-end data analytics and statistical inference project evaluating the business impact of a mobile application user interface change on user conversion rates and average order values.

---

## 📊 Project Overview

This repository contains a full-scale optimization analysis based on an A/B test conducted by **GloBox**, an e-commerce platform. The experiment evaluates whether a newly designed user interface banner/feature update significantly boosts user monetization metrics compared to the legacy layout. 

This project acts as an academic and professional blueprint for running e-commerce statistical data pipelines, moving from raw transactional logs to a definitive executive recommendation.

## 🔬 Core Learning Objectives & Technical Focus

This project demonstrates the practical application of several fundamental data science concepts:
- **Experimental Design:** Sample size validation and user partitioning tracking across a control group (Group A) and treatment group (Group B).
- **Hypothesis Testing for Discrete Metrics:** Executing a **Two-Sample Z-Test for Proportions** to determine changes in **Conversion Rate**.
- **Hypothesis Testing for Continuous Metrics:** Running a **Two-Sample T-Test for Means** to measure adjustments in **Average Amount Spent**.
- **Data Wrangling:** Processing and cleaning null parameters, tracking anomalies, and combining structural attributes like user demographics (device types, gender) with time-series interaction timestamps.
- **Data Storytelling:** Summarizing raw statistical findings into consumer-grade charts, structured executive text documents, and stakeholder slide decks.

## 📋 Data Dictionary

The analytical data layers track users down to a single granular operational row. Key columns utilized include:

| Column Name | Data Type | Description |
| :--- | :--- | :--- |
| `user_id` | Integer | Unique identifier allocated per individual customer account. |
| `group` | Character | Experimental cohort mapping: **A** (Control / Legacy UI) or **B** (Treatment / New UI Feature). |
| `device` | Character | Operating system/hardware category utilized by the user (e.g., iOS, Android). |
| `converted` | Boolean | Binary flag (`1` if the user completed at least one transaction, `0` if they did not buy). |
| `amount_spent`| Numeric | Total gross revenue generated by the user profile in USD during the tracking window. |
| `dt` | Date | Date stamp tracking the user's initial active engagement within the test timeline. |

## ⚙️ Experimental Parameters & Framework

- **Control Group (A):** Exposed to the baseline, standard mobile app interface.
- **Treatment Group (B):** Exposed to the upgraded page layout variant.
- **Significance Level ($\alpha$):** Set at $0.05$ ($95\%$ Confidence Intervals) across all exploratory statistical layers.
- **Evaluated Null Hypotheses ($H_0$):**
  1. *Conversion Rate:* The new page feature yields no change in customer purchasing behavior compared to the old layout.
  2. *Average Revenue:* The average order amount spent per user does not differ significantly between Group A and Group B.

## 🚀 Key Takeaways & Analytical Highlights

*Check the artifacts located within `/reports` and `/presentations` for explicit breakdowns of the exact calculated test coefficients, standard error variations, and visual charts.* 

1. **Conversion Metric Shift:** While the raw percentage changes point toward an adjustment in conversions, the standard error boundaries require robust statistical testing to prove whether a true, repeatable lift occurred or if it was caused by natural statistical variance.
2. **Monetization Impact:** By running independent two-sample t-tests isolated only to paying buyers, we reveal the impact of the interface change on high-intent consumer cohorts.
3. **Platform Nuances:** Segregating tracking data by device types (iOS vs. Android) highlights whether technical performance limits or operating system variations influenced user purchasing habits.

## 🛠️ How to Extend This Project (For Learners)

If you are a student or a fellow data professional looking to practice your skills, feel free to clone this repository and try the following enhancements:
1. **Sample Ratio Mismatch (SRM):** Run a Chi-Square goodness-of-fit test on the user counts to confirm whether the assignment tool split traffic cleanly without bias ($50/50$).
2. **Power Analysis:** Calculate the post-hoc statistical power ($1-\beta$) to find out if the sample size was large enough to reliably detect small changes in behavior.
3. **Segmentation Modeling:** Apply a logistic regression classifier using `device` and `group` as inputs to evaluate cross-segment behaviors.
